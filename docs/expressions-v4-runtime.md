# 新动作与休息行为接入

2026-09-20 用户返回52—98共47段视频，授权接入、检查尺寸/高度与行为树，增加睡姿并列出缺片。以编号及视频实际内容匹配动作，不根据71、92等文件的口语名称覆盖已经确认的姿态。

## 行为

- 地面安静30秒（原60秒）进入趴卧D、侧躺A、露肚B、舒展X或掩面M；完整播放进入过渡，呼吸为主要停留状态。原图包的C对应运行图的X，原有蜷睡C保留。
- 地面大躺姿按全部新躺姿及伸展帧测得的最大横向范围避让，不塞进猫窝；窝内继续使用已验收的蜷睡与窝沿遮挡。
- 每60—180秒才可能同姿态哈欠/叫/伸展或经已有过渡换睡姿，掩面保持睡眠；不因休息期限到点起来漫游。
- A/B/X使用固定15秒的点击窗口：第一击轻抖，第二击回头回应，第三击分别70/74/78直接起身。快速点击只保留最高待执行档，当前短反应完整回接后执行，不堆叠无用动作。15秒边界含浮点容差，第二击不续期。
- 掩面一次点击立即触发85放爪到A，照料时85→70→行走。拖拽立即保留实际当前姿态；暂缺新躺姿接入旧悬空姿态的素材，不硬切前坐。落下后由当前姿态继续已有退出路径。
- 只有已经接近实际屏幕左右边界、附近无物品时才短暂扶墙；按两侧独立前掌位置贴边，后脚支撑，完整落地后离开。窗口尺寸改变时同步墙面定位，不吸附应用窗口。
- 走路叫86/87只在每第三次行程且剩余位移足够完整播放时插入一次，使用原时长与位移预算；短行程不插入，不为叫声越过目标。坐叫88最多每5分钟一次，起身后的站立伸展93/94保留原时长。
- 照料期限、实际摄入与库存、食水头部2.25倍速、埋砂及全屏避让保持。新睡姿不会挡住到期照料或拖拽。

## 为什么吃完曾先坐下再走

手动动作的收尾函数先设置sit，下一更新才执行物品避让。这让24的站姿被07变成正面坐姿，然后08重新起身左走。本次改为结束时先判断是否需要离开碗旁，站姿直接接15转左→12起步→行走→13停步。到达空位后的坐下仍可能出现：现有趴卧入口58从正面坐姿开始，目前没有站立直接趴下素材。

## 检测与边界

原视频按字节保留；原帧数/帧率保留，左右不镜像。使用既有透明提取、共同姿态毛发特征配准和实际支撑ROI。初次提取发现扶墙后脚及侧躺伸腿碰到旧512画布边界，改为640透明画布：每像素仍为0.5625逻辑单位；未裁切帧只扩透明边，受影响帧从原视频重提，保持原有猫体比例。逐帧检测器新增全部新动作的合法共享姿态接缝；宽、高、位移及支撑提示分别保留。比例/透视变化属于原视频时，不以轮廓总高度归一化修补。

11条翻身/起身/掩面过渡的自动ROI曾误跟随尾巴，已改为逐段人工核对的脚掌/胸腹支撑关键点并平滑交接，共同姿态端点仍由配准约束；数值见tools/expression_support_keys.py。没有对帧外框归一化，也没有改变原动作时长。

## 重建入口

原片已在returned时，运行`py -3 tools/install_expression_videos.py`提取，再运行`py -3 tools/calibrate_expression_contacts.py`完成共同姿态和支撑标注。`expand_expression_canvas.py`仅用于本次旧512提取结果的恢复；新提取默认640，不需重复恢复。`expression_support_keys.py`支持只更新已配准素材的11条人工支撑曲线。检测使用`check_runtime_assets.py`、`check_hd_video.py`及`check-animation.ps1`，后者覆盖实际WPF像素、相邻帧、循环和已登记接缝。

正式安装：原存档备份before-expressions-v4-20260920-132231，发布根文件、manifest与4823个新增PNG哈希全部一致；安装位置dist/Chenpi。

性能边界：沿用既有全帧预加载，新增素材后正式进程工作集实测约3077MiB；运行正常，但尚不满足低内存目标，需要后续缓存优化。
