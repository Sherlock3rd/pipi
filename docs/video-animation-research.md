# B 原画偏差与视频动画路线调研

日期：2026-09-17。范围：解释现有小样偏差、查证公开案例、评估下一次试验；不是更换渲染架构的决定。本次未安装外部产品、调用视频生成服务或运行第三方代码。

## 本次偏差的来源

用户连续反馈鼻口及整体与 B 原画差异明显，现有小样不批准为角色母版。

制作记录表明：首次给 image_gen 整张六格风格板与照片，要求重新生成六个连续姿态；并未固定原画像素、拆层绑定或使用视频模型。它得到的是重新解释的造型，原画柔软的口鼻、眼脸比例和块面笔触发生变化。后两次在这组衍生图上修透明背景、局部鼻口，仍以已经偏移的全身造型为底。仅改嘴不能恢复整个头脸与画法。

缩到 192×208 会削弱细节，但不是初始造型改变的全部原因。把已有六帧编码成视频也不会恢复原画。该失败属于本轮生成和验收流程，不能推出“序列帧不能保留厚涂风格”。

## 制作与播放分别决策

**图生视频制作动作**：使用 B 原画中选定的单只猫作为首帧，固定镜头、构图、体型，只描述所需动作。[Runway 官方说明](https://help.runwayml.com/hc/en-us/articles/48324313115155-Image-to-Video-Prompting-Guide)将输入图作为首帧及风格／构图依据。这比本轮重新画六格更值得试验，但是否更像必须实测，不能保证全片脸型、毛纹或 2D 风格不漂移。

**直接以视频播放**：可让行为树选择待机、入睡、睡眠、醒来、吃饭等独立短片。仍需事件、循环、打断与过渡；不用一整段长片决定玩家何时能操作。透明背景必须贯穿导出、解码和窗口合成。[Chrome 官方透明视频说明](https://developer.chrome.com/blog/alpha-transparency-in-chrome-video)提供 WebM Alpha 支持及制作流程；普通无 alpha 的 MP4 不会因为桌宠窗口透明就自动去背景。

本项目当前 `src/Chenpi/Scene.cs` 的素材加载限定 `.png`，缓存 `BitmapImage`，按动作时间选帧后 `DrawImage`。因此不能直接把资源路径换成视频。需要新增合适的解码／透明渲染后端，原有照料、位置、判定与行为逻辑可继续驱动播放器；实际改动范围需原型验证，不能声称零成本或必须重写全部系统。

## 建议试验（尚未执行／未定型）

1. 从 B 原画提取选中单猫，优先保留原画像素与笔触，先确认静态角色；停止把当前偏移试样当母版继续修。
2. 用同一母图做 3～5 秒固定镜头端坐眨眼／呼吸视频，小动作先验证身份；逐段复杂动作以后做。
3. 审查首帧、中段、末帧：鼻口、眼脸比例、笔触、脚底漂移、2D 风格、闭环；透明处理后再次看深浅背景。
4. 同源视频制作直接透明视频与抽帧两种播放样本，比较点击立刻唤醒、拎起中断、重复循环、资源占用。性能取实测，不预设视频必然更轻／更卡。
5. 行走片段应让猫在本地画布原地迈步，由程序移动角色；吃喝片段单独对齐盆锚点。猫窝／食水盆／砂盆继续独立可移动，不能烘焙进固定背景视频。

当前工具清单未发现可调用的视频生成能力；本次没有生成视频。用户在询问可行性与案例，尚未指定视频服务、费用或全局架构替换。
