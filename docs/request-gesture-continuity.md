# 照料示意补给衔接与盆前定位

2026-09-20 用户反馈：加水后示意动作立刻跳变，加粮示意没有对齐食盆。

## 原因与修复

- 补给原来直接切换逻辑动作，站姿示意49被坐姿致谢51立刻替换，既截断当前循环，也绕过SR→F的07坐下过渡。正面请求45/46补给时也会在任意帧切回待机。
- 现在补给仍立即加一层、清除对应请求；视觉进入care-finish，保留当前循环剩余帧，到共同姿态端点后通过图中的真实过渡。带路后的序列为48/49/50→07→51；未带路的45/46/47完成后回正面待机。之后恢复到期照料，示意/致谢不扣库存、不重排期限。拖拽等明确输入仍立即响应。
- 加粮45是正面坐姿前伸爪，爪的横向位置接近角色根节点；此前错误复用吃饭嘴部的+94偏移。现在正面食水请求根节点位于对应盆中心，站姿48/49及吃喝继续使用盆左94的落点。换阶段或拖动物品仍通过真实走路到达，不瞬移猫或物品。
- 精确24Hz回放暴露浮点数落在整数帧边界下方的问题，修正帧索引的数值容差，保证末帧正常显示；不增加等待帧、缩放、叠图或变更原片时长。

## 验证

507项检查通过。新增覆盖食/水、正面请求/站姿示意、循环内五个补给时刻，检查同一时刻原帧保持、末帧/07过渡、固定根节点、库存/期限不变、随后实际摄入，以及提起中断和24Hz边界。

WPF审计复用实际DrawVideoFrame与DrawBowl，分别导出正面加粮与站姿补水前后及全序列。检测器扫描9段1042帧、1052对相邻帧/循环/接缝；源片内部178个阈值标记、98个复核项继续保留，包括转身与坐下姿态变化，不能宣称原片全部美术通过。核对最大标记为07转身过程中轮廓变化；本轮没有改源PNG或动画几何。

实际补水序列额外扫描326帧/325对，保留61个原片姿态阈值标记、45个复核项；它们不等于本轮路由失败，也没有被删掉作为“全片零异常”。

6处相关共同姿态接缝全部通过：躯干宽度差不超过0.127%，高度差不超过0.071%，实测承重前脚高度差最多0.5逻辑单位。正面加粮第48帧伸爪点与盆中心横向差由96.07降至2.07逻辑单位。旧49中途→51的错误直切作为负对照保留，使用姿态轮廓差检出，而非把完全不同姿态的拟合解释为缩放。

结构化证据见[verification.json](qa/request-gestures/verification.json)。原始截图与序列在本地artifacts/request-gesture-fix，自动化WPF渲染不冒充人工鼠标端到端操作。

## 重跑

1. 发布程序后用`--audit-animations <目录>/before --audit-clips 01,06,07,45,46,48,49,50,51`导出原帧渲染；运行`tools/check_animation_continuity.py`，输出到`<目录>/source-monitor-final`。
2. 用`--audit-care-request <目录>/food-request-final --request-kind food`导出正面请求；用`--audit-care-request <目录>/water-guide --request-kind water --request-guided`导出站姿示意补给。
3. 执行`py -3 tools/check_request_gestures.py <目录> --out <报告.json>`。独立相邻帧检测器仍保留所有源片标记，专用检查验证路由、末帧、支撑脚、落点和补给状态。
