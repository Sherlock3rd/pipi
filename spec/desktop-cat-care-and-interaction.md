# 照料与交互补充规范

日期：2026-09-17。状态：核心原型已实现；实际验证与剩余边界见[原型验证](../docs/prototype-validation.md)。随机照料周期、缺少物品 5 分钟后中央请求及鼠标带路，以最新[随机照料与带路求助](desktop-cat-care-schedules-and-guidance.md)为准，覆盖下文早期触发默认值。

用户授权：“漏掉的内容帮我补一下，不要有不可逆惩罚，只有催促。运行时间增加饥饿和口渴，小猫实际吃喝时扣盆里的量。”

本规范落实上一轮补充项。未由用户指定的操作细节采用下文明确的产品默认值，便于后续调整；不据此选择框架、安装后台或增加新玩法。

## 1. 照料循环与无惩罚原则

- 系统有效运行时间只增加饥饿与口渴需求，**不直接扣除饭盆、水盆库存**。
- 电脑关机、睡眠、休眠期间不增加需求。桌宠完全退出但电脑运行时，仍累积需求；再次启动补结算需求，不模拟不可见的吃喝、不追扣库存。
- 全屏隐藏时桌宠仍在运行，照料模拟可继续，实际模拟执行的吃喝动作正常结算；画面隐藏与程序退出是不同状态。
- 猫有需求且盆中有资源时，可以选择走到对应盆边吃喝；缺资源才催促主人补充。
- 吃喝按实际完成的动作事件结算：扣对应库存，同时降低对应需求。库存不足时仅消耗剩余量，需求按实际消耗量改善。
- 吃喝中被拖拽／点击打断，已完成的结算保留，未发生的事件不扣库存；恢复或重新规划不会重复扣除。
- 饥饿、口渴和库存有上／下限，不能负库存或无限累积需求。阈值、增长速度和每口消耗量集中配置，待原型调节。
- **未照料的负面反馈只有催促**。缺粮、缺水、猫砂脏不触发死亡、离家、生病惩罚、永久掉属性、关系受损、罚款或操作锁定，也不强制付费补救。
- 饥饿或口渴达到上限仍可点击、拖拽、入窝、唤醒及照料；不能因饥渴锁死在催促树中。
- 猫砂脏时催促清理，不增加随地排泄等惩罚玩法。猫砂状态不直接降低饥饿／口渴或阻止吃喝。

## 2. 时间口径

| 用途 | 计时规则 |
| --- | --- |
| 昼夜作息与日期皮肤 | 按本地系统日期／时段判定；日期皮肤仍后续制作 |
| 饥饿与口渴增长 | 按系统有效运行时长，包括桌宠退出后的时间；排除关机、睡眠、休眠；锁屏但系统运行继续累计 |
| 猫窝陪伴时长 | 从首次运行起经过的自然时间，包括程序退出与电脑关机，重启程序不重置 |
| 动画与移动 | 独立的短时间步长，挂起恢复不让猫瞬移，不快速补播积压动作 |

时间调整不得使库存直接变化；首次运行时间、有效时长结算点分别保存。异常校时造成负陪伴时长时显示非负值并保留原始领养时间。跨重启计时技术方案仍须验证，不能以自然时间差替代有效时长。

## 3. 点击、拖拽与猫窝

- 短按释放触发点击互动；达到长按阈值后进入拖拽，播放被拎起反馈，并取消本次点击事件。
- 长按阈值和移动容差可配置，原型阶段调节，不把任意像素抖动当作拖拽。
- 拖到猫窝有效区域时高亮；**释放才确认入窝**，仅经过或悬停不自动入窝。窝外释放播放放下动作，再恢复自主行为。
- 入窝后播放入窝、入睡、睡眠循环；点击立即唤醒并进入醒来／出窝动作；作息或需求也能自然唤醒。
- 猫窝高亮以同一命中规则驱动，视觉提示与实际释放结果必须一致；睡猫的可点击区域与猫窝计时文字互不冲突。
- 修复补充：猫脚靠近猫窝或松手位置处于可见猫窝区域均视为放入，支持从头部拎起；松手先同步最终位置。入窝后 15 秒安定期禁止自动照料立即抢占，但点击可立即唤醒，之后需求可自然唤醒。
- 拖拽中失焦、切全屏或显示器移除，取消拖拽并恢复到最近有效位置；不遗留悬空锁定状态，不穿越到屏幕外。
- 默认点击饭盆／水盆补满对应容量，已满时不溢出、不叠加；点击猫砂盆清理全部，已干净时保持状态。操作给出短暂视觉反馈。

## 4. 催促与无互动卖萌

- 求粮、求水、求铲屎各有独立序列帧；缺少多种照料时轮流表达，同一时刻只播放一种催促。
- 每种催促及整体催促均有冷却，持续缺资源不能每帧重触发、持续叫或连续刷提示。冷却长度集中配置。
- 补粮／补水／清理后立即撤销对应过期催促，并重新评估行为；补盆不直接消除猫自身饥饿／口渴，仍需实际吃喝。
- 增加静音和音量设置，静音保留可见动作；全屏避让期间不播放叫声或弹出打扰提示，退出全屏不补播积压催促。
- 无互动时长按桌宠内成功交互计：点猫、拖拽、补粮、补水、铲屎均会重置；鼠标仅经过不重置，不读取其他软件键盘内容。
- 无互动卖萌有独立冷却，不强制唤醒睡猫，也不打断正在吃喝、如厕或用户拖拽。
- 提醒不抢键盘焦点，不强制置顶。首版通过动作和可选声音表达，不增加常驻数字需求面板；气泡样式仍可后续讨论。
- 最新覆盖：用户禁止所有角色文本台词，取消气泡方案；靠近对应盆、伸爪、舔嘴、刨地等动作表达照料需要。去除拖拽文字、睡眠字母、互动台词和当前行为文本面板。设置控件与原定陪伴计时保留。

## 5. 找回、布局和存档

- 托盘提供设置、显示／隐藏场景、召回猫猫、恢复默认布局和退出桌宠入口。
- “召回猫猫”把猫带回猫窝附近的可见位置，不强制睡觉，不改变粮水或猫砂状态；“恢复默认布局”恢复物件位置，不重置养成和首次运行时间。
- 提供整组缩放；缩放同步命中区域、移动边界和接触锚点。五物件随桌面／悬浮模式统一切换层级。
- 分辨率、DPI、任务栏或连接的显示器变化后，将不可见物件约束回有效桌面区域。多屏全屏避让范围在桌面验证阶段确定。
- 食水满／少／空、猫砂干净／脏均有可辨识图像状态；反馈不能挡住猫或长期遮挡桌面。
- 用户新增：食水量、饥渴和猫砂状态不标具体数值。用粮粒数量、水面大小／波纹、结块表现；补给有平滑动画。默认紧凑排列，四件家具均可单独拖动且记住位置。物件移动超过阈值即拖动，猫仍长按拖拽；拖动释放不触发补给／清理。睡猫随窝搬动，移动正在使用的盆会中断当前动作并重新寻路。
- 保存首次运行时间、累计有效时长及结算点、饥渴需求、盆库存、猫砂状态、猫和物件位置、缩放、自启／显示／声音设置。
- 正常退出、关键照料操作及周期性检查点保存；采用原子替换、最近有效备份与版本迁移。库存变化、需求恢复和结算标记作为同一状态保存，避免重复扣粮。
- 重启时恢复最后有效状态；无法恢复全部状态时优先保留可读存档和首次运行时间，不静默清空后伪装为首次领养。
- UI 自启开关与退出后计时组件的职责分开；计时组件采用何种实现仍未决定，应透明展示运行状态与停用方式。

## 6. 动画与开发支持

- 补齐被拎起／悬空／放下、入窝／入睡／睡眠／醒来／出窝、如厕／埋砂等过渡与独立序列帧，具体帧数待素材验证。
- 猫窝分前后遮挡层，饭盆、水盆、猫砂盆提供相应接触点与遮挡关系。换蓝猫素材时通过资源清单调整，避免在行为逻辑中硬编码某只猫的像素尺寸。
- 开发模式提供时间加速、指定时段、强制行为、当前行为原因与命中区显示；不作为普通玩家的常驻界面。

## 7. 验收场景

1. 猫保持不吃喝而经过有效运行时间：需求增加，盆库存不变。
2. 猫实际吃喝：只扣对应库存，需求按摄入量下降；动作中断、重新进入或读档不重复扣除。
3. 完全退出桌宠、电脑继续运行后重开：补增需求，不凭空扣盆库存；期间睡眠／休眠不计入需求增长。
4. 长期缺粮、缺水、砂盆脏：只有有冷却的催促，仍可互动和照料，无惩罚／永久损失。
5. 经过猫窝但没释放不入窝，窝内释放才睡觉；点击与自然唤醒都可用。
6. 多种照料缺失时不叠加叫声；解决一项不继续催促该项；静音及全屏期间不打扰。
7. 重开、缩放、断开显示器后能找回猫和物件；召回及布局重置不影响库存和陪伴时间。

这些是完整验收要求；原型已覆盖其中一部分，已测／待测边界见[原型验证](../docs/prototype-validation.md)，不能以逻辑测试代替所有桌面实测。
