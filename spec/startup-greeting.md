# 独立启动开场

依据：2026-09-20用户要求新增开机自启/首次运行的连续开场；随后明确“等独立跑步素材补齐后再启用开场”。

状态：**流程设计与制作包已完成，自动触发和演出执行尚未接入，开场未启用。** 行为工作台中的“启动开场 · 待素材”是可点选的设计总览，不是假装正在执行的行为节点。现有53项行为参数与Windows自启选项保持原状。

## 连续动作

猫窝睡眠 → 醒来离窝 → 快速跑到屏幕中部 → 短距离来回踱步并回中点 → 转为正面四足站立并朝前蹭头 → 站着连续叫三次 → 中部坐定 → 正常行为树。

中部取当前工作区中央附近的可坐空位；不能为严格居中而坐进食盆、猫砂或其他家具。家具可移动，因此整段以共用首尾的模块连续编排，角色视频不烘焙猫窝或固定屏幕坐标。正面蹭头和三连叫必须保持站姿，最后才坐下。

首尾约束：旧蜷睡C，侧坐I，右/左站SR/SL，新跑步相位RR/RL，新正面四足SF，最后正面坐姿F。新舒展记作X，避免与旧蜷睡C混名。动画编号与资料唯一清单见[待补合集](../art/video-pipeline/completion-v5/README.md)，结构化方案为[启动流程JSON](../art/video-pipeline/completion-v5/startup-greeting.json)。

## 触发与退出设计

- 首次成功加载且可显示的新用户运行；Windows开机自启时每个启动周期一次。两个条件同时命中只演出一次。
- 普通退出再开、桌面/悬浮宿主重建、休眠恢复、打开设置不触发。旧用户普通更新启动不冒充首次运行。
- 待接入时将去重标记在开场开始时持久化，用户中断或程序退出不反复重播。损坏存档恢复不冒充新用户。
- 手动点击/拖拽/照料命令可取消；取消需沿已有合法姿态退出，不能生硬跳姿。普通悬停不自动打断连续开场。
- 全屏与用户隐藏暂停开场的表演进度，仍按既有规则累计真实照料时间；恢复后继续，不在后台偷播完。
- 照料期限、库存和缺货起点保留，开场不消费、不补给、不重抽期限。完整坐定后恢复正常优先级，包括已到期照料。
- 117视频内严格三次开合嘴，声音按三处峰值同步，静音时仍有动作；现有合成提示音不等于最终猫叫音效。

## 待接入条件

必需108—118共11段、RR/RL/SF三个新锚点；优先补99/100侧坐直接起身以缩短绕路，现有21→18→06/08为有效旧路径。跑步不得用现有步行提速顶替。

返片后再进行透明提取、共同姿态校准、跑步根位移/速度拟合、逐帧/循环/接缝与承重脚检查、左右离窝/窝沿场景审计，然后实现与验证触发去重、输入取消、全屏暂停、三叫计数和交回普通调度。达到上述条件后按用户本轮授权启用；不把现有设计页当成已实现的启动播放。

窝内等待、踱步范围与往返数、真实跑步速度待返片接入时成为可调参数。制作建议与当前生效参数分开，三连叫次数保持用户指定的3次。
