# 桌面蓝猫：实现计划与待定设计

日期：2026-09-17。状态：用户已授权开工，Windows 原型已实现并打包，阶段 0–3、5 部分完成；当前采用 WPF / .NET 10，保留跨重启计时和完整桌面验收缺口。产品需求入口为[需求简述](desktop-cat-brief.md)，已测范围见[原型验证](../docs/prototype-validation.md)。

本轮已补充确认三项：桌宠完全退出后仍按系统有效运行时间消耗，睡眠／休眠暂停；游戏／视频／F11 全屏隐藏，普通最大化可悬浮；入窝后可点击立即唤醒，也能按作息／需求自然醒。

最新口径：上述“消耗”指有效运行时间增加饥饿和口渴，库存仅在实际吃喝时扣除。程序退出期间只累积需求，重开不补扣库存。未照料只有催促，没有惩罚。上一轮遗漏建议已按用户授权纳入补充规范，不再作为待接受提案。

最新交互覆盖：原地长时间休息、5 分钟入睡、悬停蹭鼠标、逗猫棒、拎起转换优化已实现；全程无角色文本台词，扩大五倍的判定范围不显示光圈。现行规则见[休息与玩耍](desktop-cat-play-and-rest.md)，原计划中的文字／气泡候选不再适用。

| 3：行为树与动作调度 | 自由移动、睡觉、吃喝、如厕掩埋、索要照料、无互动卖萌；分离行为选择与动作播放 | 猫能走到目标物件执行动作；用户输入可安全打断；状态变更可重新规划；长动画无重入、提醒无每帧重复触发；有调试视图说明当前行为与原因 |

## 首先验证桌面行为

- 真正“桌面层级”不等于普通窗口取消置顶。需要明确在壁纸／图标、普通窗口、任务栏之间的层次及点击关系，并测试 Win+D 和资源管理器重启。
- “置顶但避让全屏”也不是一个永久置顶开关；要检测前台应用及所在显示器，退出全屏后恢复用户原设置，不能偷偷改变设置值。
- 普通最大化与全屏分别列测试用例：用户已确认仅避让游戏／视频／F11 等全屏，普通最大化仍可悬浮。建议只隐藏发生全屏的屏幕上的场景，首版也可先限定一块屏幕；多屏范围未定。
- 整个五物件场景统一切换层级和全屏避让，避免猫悬浮但饭盆仍在背后。桌面空白区域要能正常点到图标与其他应用。
- 技术评估以当前 Windows 环境为起点，跨平台并非已经承诺。候选优先验证原生窗口集成能力，框架依然待定。

## 三类时间必须分开

| 时间 | 用途 | 处理建议 |
| --- | --- | --- |
| 本地系统日历时间 | 昼夜作息、指定日期皮肤、首次运行至今 | 保存首次运行的 UTC 时间戳，用本地时间展示／判定日期；系统校时、时区和跨日重新评价一次，避免重复发事件 |
| 有效运行时长 | 饥饿／口渴需求增长，不直接扣盆库存 | 包含桌宠完全退出后的系统运行时间，排除关机、睡眠／休眠；锁屏但系统运行继续累计；不以简单日历时间差代替 |
| 动画与移动步长 | 播帧、行走、过渡 | 单调计时，小步模拟；长挂起后限制单次步长，不让猫瞬移或跳过全部动作 |

分开记录：盆里剩余量、小猫饥饿／口渴、猫砂脏污程度、睡眠状态、距上次互动时间。盆容量和猫自身需求是两类数据，避免出现饭盆有粮但猫永远不吃，或吃饭时重复扣粮。

已选定：按有效时间增长需求，猫实际吃喝时扣盆库存并降低相应需求。取消“盆库存随时间自动减少”的候选方案。程序退出期间不模拟吃喝、不扣库存；重开只补结算需求。具体事件结算、边界和验收见补充规范。

用户已要求桌宠彻底退出后仍计算系统有效运行时间，需要额外的跨会话记录方案。单次开机的时长计数可帮助补算同次开机内的间隔，但无法单凭当前计数恢复多次重启之间的历史。

阶段 0 比较两条路线：独立轻量计时组件，或通过可靠的系统历史记录重建区间。前者必须透明说明桌宠退出后仍有计时组件工作、如何停用及其资源消耗；不能把“主界面退出但主进程仍在”谎称完全退出。后者必须验证事件缺失、权限、日志清理、快速启动和异常关机的准确性，不能默认系统日志总完整。

“开机显示猫猫”的设置与“后台计时”的职责必须分开，用户关闭界面自启不应悄悄改变消耗规则。计时安装方式尚未决定，本轮不安装后台服务／计划任务。缺失历史区间不得用自然时间差冒充系统运行时长，需约定可恢复的降级处理并显式标记误差。

## 交互规则

- 点击在释放时判定；达到长按阈值后进入拖拽，抑制本次点击。长按时给“被拎起”反馈，避免用户不知道是否触发。
- 拖到猫窝时高亮，释放才确认入窝；仅悬停不触发，释放到窝外恢复其他行为。此项随用户本轮“补齐遗漏内容”授权纳入默认操作。
- 用户已确认入窝睡眠支持点击立即唤醒，也会按作息／需求自然醒。自然醒的需求阈值、最短睡眠段和睡眠恢复速度待设计；用户主动拖回窝后建议避免瞬间又出窝，但不能因此禁用需求唤醒。
- 默认点击饭盆／水盆补满，点击砂盆清理全部；满盆和干净砂盆重复操作保持状态并给反馈，补充库存不直接消除猫的饥渴。
- 猫移动时点击、按住时被屏幕边界限制、拖拽中切全屏或失焦、用户唤醒与自动如厕同时发生，都需显式取消／恢复规则。

## 行为树建议结构

先处理外部控制，再评价需要，再执行日常行为；数值和紧急阈值后续确定。

```text
输入／运行状态门控
├─ 拖拽中 → 暂停自主决策，播放被拎起循环
├─ 用户点击 → 在允许的打断点播放互动或唤醒
└─ 自主选择
   ├─ 必要照料 → 去饭盆／水盆／砂盆 → 执行动作
   │  └─ 资源为空／砂盆脏 → 请求主人处理 → 冷却后再评估
   ├─ 睡眠需求／作息 → 回窝或睡觉（位置规则待定）
   ├─ 长时间无互动 → 卖萌 → 冷却
   └─ 自由移动／待机 → 随机短段行动 → 再评估
```

- 拖拽、睡觉、互动是互斥动作；吃饭、喝水和如厕不能并发。
- 行为树负责决定做什么，动作播放器负责前摇／循环／收尾与可打断点；不要把每帧决策重启成一个新动作。
- 提醒设置冷却、合并多个需求并提供静音／音量控制；全屏期间不叫喊、不弹出提示，回来不补播。气泡表现仍待设计。卖萌有冷却，不打断睡猫、吃喝、如厕或用户拖拽。
- 请求被满足后立即撤销旧请求，不继续播放“缺水”提醒。
- 未照料只有催促，不加入死亡、离家、生病惩罚、永久属性／关系损失、罚款或操作锁定；这是用户确定规则，不仅是首版建议。

## 序列帧清单草案

每类有独立资源 ID 和序列帧，不将同一段待机动画重复标记为多个行为。具体帧数、速度与风格在素材验证后确定。

| 行为组 | 建议拆分的序列 |
| --- | --- |
| 日常 | 站／坐待机、朝左走、朝右走、停步转向 |
| 用户点击 | 被摸／开心互动 |
| 拖拽 | 被拎起、悬空循环、放下 |
| 猫窝睡眠 | 入窝、蜷缩入睡、睡眠循环、醒来、出窝 |
| 吃饭 | 靠近后低头、吃饭循环、收尾舔嘴 |
| 喝水 | 低头、舔水循环、收尾 |
| 猫砂盆 | 进入、蹲下排便、埋砂、离开 |
| 催促 | 求喂饭、求加水、求铲屎，需可辨识的独立表现 |
| 无互动 | 至少一套卖萌动作，具体表现由用户选定 |

资源协议记录帧尺寸、时长、循环区间、接触锚点、事件帧、朝向、可打断点；非对称美术不能一律镜像。猫窝分前后遮挡层，让猫入窝后身体被窝沿正确遮挡；盆和猫砂盆同理。粮／水满空与砂盆净脏也需要可辨状态图。协议具体格式在原型阶段选择。

节日围脖可预留颈部锚点，但需逐动作校验遮挡和跟随；复杂角度可能需要单独皮肤帧，不承诺贴一张围脖就支持全部动作。hatch-pet 的 Codex 图集约定不直接规定本项目动作数量。

## 已纳入的支持项

1. **可找回与可退出**：托盘入口、重置布局、召回小猫；避免场景被覆盖后找不到设置。
2. **存档**：第一次领养时间、资源量、猫砂状态、位置、设置；原子写入与备份、异常退出恢复、版本升级迁移。
3. **打扰控制**：叫声静音／音量、提醒频率、全屏勿扰；是否显示需求气泡由用户决定。
4. **桌面适配**：DPI、任务栏位置、多显示器断开、分辨率变化、物件不落到屏幕外；整组缩放与默认布局恢复。用户已新增自由拖动物件和紧凑默认布局，已纳入原型。
5. **可感知的状态**：食水量、猫砂净脏、点击成功反馈；可用图像状态表达，不一定加常驻数字面板。
6. **自然程度**：猫的移动范围、目标停靠点、日夜活动权重和无互动判断；不要通过收集全局按键文字判断互动。
7. **不在场政策**：程序退出、电脑睡眠、锁屏和全屏分别处理；隐藏画面不自动等于暂停照料。
8. **测试工具**：加速时间、跳到某时段、强制行为、显示命中区；仅在开发模式使用，降低动画和等待验证成本。

## 技术资料与验证边界

- [Windows Time](https://learn.microsoft.com/en-us/windows/win32/sysinfo/windows-time)：GetTickCount 类时间包含睡眠／休眠，QueryUnbiasedInterruptTime 只含工作状态；不能混用消耗口径。
- [通知状态枚举](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/ne-shellapi-query_user_notification_state)：区分锁屏、忙碌、独占全屏和演示状态，可作为勿扰信号，不单独证明所有无边框全屏都能准确识别。
- [SetParent](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setparent)：涉及原生父子窗口和样式／DPI约束；并不保证某一桌面宿主方案跨所有 Windows 版本稳定。

上述资料支持将窗口和计时放在最先验证的位置，不构成已实现承诺。
