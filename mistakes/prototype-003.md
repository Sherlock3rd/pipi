# PROTOTYPE-003：切换悬浮后透明窗口不恢复显示

- 日期：2026-09-17。
- 分类：窗口宿主／运行中切换。
- 状态：已修复，悬浮→桌面→悬浮实机验证通过。
- 用户确认触发点：小猫设置里的“悬浮在普通窗口上（全屏时隐藏）”开关。

## 事实与影响

隔离存档复现切换后猫和物件不再正常显示。诊断同时显示原生窗口 Visible、场景 Visible、fullScreen=false、动画帧数继续增加、坐标仍在屏内；不能把这个现象解释为全屏自动隐藏或存档丢失。旧设置文字也不会随切换刷新。

## 根因

旧方案在同一个正在显示的 WPF 透明 HWND 上直接切换 Explorer 子窗口和悬浮顶层窗口，未重建对应的渲染宿主。本机出现状态仍有效但画面不再呈现的问题。只检查 SetParent 的父句柄，不能证明透明画面还在桌面上。桌面模式的扩展样式在切回时也未清理，原浮动分支不显式重新布置窗口尺寸与位置。

## 修复与验证

- 切换时创建新的显示窗口，复用原 PetEngine 实例，保留行为、照料期限、陪伴、位置和隐藏偏好；释放旧帧订阅、计时器、提示音订阅与托盘，避免重复更新。
- 新宿主仅继承运行期诊断选项，不重放 `--floating`、`--settings` 等一次性启动操作；旧快照回调不会关闭新窗口。Loaded 初始化只执行一次。
- 初始挂接显式设置目标位置、大小、显示标记及对应样式。设置窗口保留位置，模式说明实时更新。
- 隔离测试真实点击完成悬浮→桌面→悬浮，恢复后桌面截图可见猫和全部家具；新 HWND 与诊断状态一致，位置保留。83 项既有检查通过。未以此声称覆盖真实游戏全屏、所有桌面主题或混合 DPI。

## 同类防呆

层级切换必须验证完整往返和实际画面，不能只检查进程存在、父句柄或场景导出图。透明窗口换宿主时显式清理旧回调、共享实时模型，防止双计时与重置进度。

API 样式顺序依据：[Microsoft SetParent](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setparent)、[SetWindowPos](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowpos)。WPF 本机显示故障结论来自上述复现，不将其泛化为所有平台的 API 行为。

2026-09-19 发布补记：Stop-Process 返回后立即覆盖仍遇到DLL占用，导致首轮复制失败；确认旧进程退出后完整重复制并核对DLL/manifest哈希恢复。今后停止精确路径的本项目进程后必须Wait-Process，复制遇错即停止，哈希一致才启动，不能把发出停止请求等同于锁已释放。
