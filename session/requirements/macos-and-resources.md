# macOS 适配与资源优化

## 授权

2026-10-08，用户要求“解决一下mac的适配”，追加“不降低画质和流程性的前提下，同时也优化一下包体大小和运行内存占用”，并确认 Apple 芯片与 Intel 都需要。沿用现有设计、动作流程及本项目 Git 提交推送授权。

## 当前交付

新增 macOS 桌面宿主与两种架构发布脚本；共用原行为、几何与绘图；原始资产未修改。全量 15,349 帧经无损压缩和逐像素回查，发布素材减少 46.6%。缓存由全量预载改为 96 MiB 的滚动预读与 LRU，弱引用边界表避免旧帧滞留。

761 项共享检查、13 项 Windows 窗口检查和两端编译通过。WPF 全部 15349 帧实际解码/预乘/裁切像素与边界零差异。单独运行完整 60 秒开场预览工作集约 311 MB、P95 帧间隔 17.56 ms；五分钟实测约 297—351 MB、峰值约 389 MB。宏观流程与动作时长保留。用户正式 Windows 安装、个人存档、自启和行为参数未改动。

用户指出的 CI 37734213003 失败是 Intel P95 90.30 ms 超过 45 ms 门槛；不能删门槛宣称修复。分阶段诊断定位到 Skia GPU 着色器编译超时，Intel 改用保留全效果的软件光栅路径，后续五分钟回查发现 Apple 芯片 Metal 原生内存仍持续增长，最终两端统一软件光栅。原生窗口状态只在变化时写入，解码直接读原生缓冲并复用中转数组；420 帧对照独立旧算法且覆写回收缓冲后像素/边界仍一致。

最终原生构建 37739873431 双架构全部通过：原生普通/全屏窗口、层级/穿透/非激活、参数工作台回读、解压安装包签名、原生像素审计及两组 85 秒完整开场。Apple 芯片 P95 18.74/18.75 ms，Intel 36.11/36.03 ms；对应预览/桌面结束工作集约 443/443 MB 和 353/381 MB。Mac 15+，两包自包含，无需 .NET；ad-hoc 签名未公证，首次打开按系统提示批准。原生 CI 不代替真实游戏、Spaces、Retina、拖拽和声音硬件手工体验。下载及证据见 `docs/macos-and-resources.md`。

五分钟进程 RSS 对照：Apple 芯片软件光栅 425—429 MB、P95 18.70 ms，Intel 336—373 MB、P95 34.90 ms；两者后期中位数均未增长。旧 Metal 样本约 704 MB 涨至 1136 MB，作为失败基线保留，不算内存通过。持续检查已新增总 RSS 中位数增长门槛，见 macos-memory-accepted.json 与 macos-memory-baseline.json。

## 2026-10-09 Mac 实机鼠标反馈

用户反馈可运行但点击、选中、拖动和猫窝右键均失效，拖动出现桌面选择框。撤回上一轮对完整交互可用的任何推断。发现桌面模式设置为壁纸层+1，低于 Finder 图标输入层；修正为桌面图标层+1，仍低于普通应用。新增通过 WindowServer 投递鼠标的原生夹具，包含旧层级负对照、补给点击、猫/家具拖拽、三档缩放、猫窝右键设置、空白穿透、普通窗口遮挡与悬浮模式。原生验证进行中，不能以编译和属性回读代替完成。
