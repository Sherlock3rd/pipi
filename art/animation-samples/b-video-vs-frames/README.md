# B 原画：同源视频与序列帧对照

用户已授权两条路都试验。本实验采用同一段图生视频，分别直接播放与抽成 PNG 序列播放，避免内容不同干扰比较。现阶段未获得视频，不能称动画效果已完成。

## 当前产物

- `index.html`：完全本地运行的对照页；原画 B、视频播放器、视频抽帧播放器；上传仅指本地选择文件，不向网络发送。
- `experiment.json`：素材来源、两条路线与当前阻塞。
- `image-to-video-prompt.md`：同源短视频生成提示和造型验收。

尚缺生成服务连接与实际视频。已发现可用但尚未安装／连接的 Runway 插件；用户连接后再核查具体生成能力与额度，不把发现插件当作生成成功。不用旧六帧编码视频冒充图生视频。

## 使用

在仓库根目录运行 `python -m http.server 8767 --bind 127.0.0.1 --directory art`，打开 `/animation-samples/b-video-vs-frames/index.html`。也可直接本地打开 HTML。选择实际生成视频，页面会按 12 fps 抽取整段（上限 10 秒、300 帧、源尺寸不超过 4096×4096），以 PNG blob 保留解码所得颜色与 alpha；两侧显示尺寸一致。可选择 24 fps 做更密集的对比。

透明源视频才有透明结果；选择普通带底色视频时两侧仍保留底色，本页不做自动抠像。浏览器解码器若不支持源视频透明通道，也不能以本页证明透明通过。展示视频播放与序列播放的可行性，不代表 WPF 集成或性能验收。

播放／暂停、从头同时播放、逐帧与背景切换用于目视评审；浏览器调度并非严密同步设备，不将肉眼差异当性能基准。切换文件时释放旧帧与 object URL。

## 验收顺序

1. 先检查原画单猫及视频首帧；不沿用被用户否决的 b-idle-v1 造型。
2. 比较鼻口、眼脸、柔和块面笔触、2D 风格；不通过时停止后续动作扩展。
3. 检查连续运动、脚底锚点、闭环、浅／深背景边缘。
4. 通过后再测试点击唤醒、拎起中断与 WPF 透明视频后端。

## 已验证／待验证

页面 JavaScript 通过 Node 语法检查；浏览器实际加载页面，显示原画依据、待视频状态及禁用播放按钮，未伪造已有动画。真实视频解码、抽帧、连续播放与透明效果尚未验证，需视频产物到位后继续。准备页不作为用户所要求的两条路线效果交付。
