- 依据：[Rules Bootstrap Spec v1.0](../spec/rules-bootstrap-spec.md)，原文复制自 `D:/gameDesign/DobeDemo/spec/rules-bootstrap-spec.md`；此前 Interview 工作区也使用此来源。
- 用户角色：本桌宠项目的产品与设计决策者。助手角色：桌宠研发协作助手，负责调研、技术实现、验证与工作区维护。这是按用户当前用途归纳的职责，不预设职业头衔。
- 当前授权：specrule 部署和调研已完成；用户明确“来吧，先做起来我看看”，已授权产品实现，随后要求重试并改为无照料数字、紧凑布局、自由拖动物件。详见[需求简述](../spec/desktop-cat-brief.md)及[实现记录](../docs/prototype-validation.md)。
- 原型采用 C# / WPF / .NET 10，SDK 在工作区 `.tools/dotnet`，分发包包含运行时。最终画风、照料数值、AI 服务、商业化与发布渠道未定；Electron 未采用。
- 不继承其他项目的自动推送或公开发布授权。
- 用户本轮明确指定本项目内容提交至 [Sherlock3rd/pipi](https://github.com/Sherlock3rd/pipi)，已授权提交与推送；该授权仅适用于此项目。推送前检查文件范围，排除运行时、构建输出、截图、个人存档和凭据，保留第三方许可证。
- 用户已授权补齐规划中的遗漏项，操作默认值与验收统一维护于[照料与交互补充规范](../spec/desktop-cat-care-and-interaction.md)。未照料只有催促，没有不可逆或其他惩罚；有效运行时间只增加饥渴需求，实际吃喝才扣盆库存。该产品规则不得在后续实现中改成库存自动流失或程序退出后补扣。
- 粮水余量和猫砂状态只用图像／动画表示，不显示具体照料数值；紧凑默认布局，物件独立拖动、保存位置，点击与拖动互斥。猫窝陪伴时长仍保留。
- 用户新增并授权：优化拎起卡顿、悬停 5 秒蹭鼠标、移动后随机停留 2～60 分钟、超过 5 分钟原地睡眠、点击唤醒／互动，以及逗猫棒拾取归位与双圈判定。最新行为优先于原型频繁漫游，见[休息与玩耍](../spec/desktop-cat-play-and-rest.md)。
- 用户追加硬性规则：全程无角色文本台词，禁止气泡、文字催促或拖拽文字提示，角色需求由行为动作传达。操作控件和既有陪伴计时保留。两个逗猫判定圈半径扩大五倍；卡顿排查重点是长按切换到拎起的瞬间。
- 最新澄清：判定光圈仅为内部逻辑，实际画面不显示。仍保留猫 390／棒 170 逻辑单位的判定半径。
- 最新逗猫规则：现有猫圈作为外圈，检测到羽毛即连续跑向目标；新增猫内圈，贴近后才抓棒，移动目标后自动恢复追跑。内圈暂定 100 逻辑单位，按羽毛实际位置检测。两个猫圈均不显示，无文字台词。

## 对话与执行原则

用户新增授权：预留点击互动与待机表现类型，待画风确定后批量加素材。实现默认各 12 类且可继续扩展；空槽不参与播放，动画池仅影响视觉、不改变行为时序与优先级。草案与接入规范见[资源说明](../assets/pets/bluecat/README.md)。

最新照料规则：独立随机喝水 10～30 分钟、吃饭 20～60 分钟、如厕 60～120 分钟；空盆或满猫砂持续 5 分钟后到屏幕下方中央请求。鼠标到猫身立即覆盖为带路，走走停停回头等玩家，终点在对应物品旁，点击补给／清理结束。全程只用动作。期限和缺货起点持久化，离线不回放库存消耗。详见[随机照料与带路求助](../spec/desktop-cat-care-schedules-and-guidance.md)。

- 所有面向用户的回复以 `you majesty` 开头；代码、文件内容和产物正文不强加称呼。
- 明确简洁执行；未经允许严禁修改设计。
- 对影响设计、权限或任务范围的不确定问题二次确认，禁止主观臆断。当前会话的明确指令即为该范围的书面授权，已经授权的事项不重复询问。
- 文档、目录和不改变设计的脚手架可以直接执行，需在 session 记录。常规实现选择按已确认目标推进；建议与已确认事实分开标记。
- “部署基础 rule／specrule 环境”优先定位已用规范及历史错题，不能理解为默认安装运行时或自行实现产品。

## 执行与验证流程

显示层级修复需验证实际画面和悬浮／桌面完整往返；原生挂接返回成功不代表画面呈现成功。重建宿主保留实时模型并清理旧订阅，避免重复计时。详见[窗口切换错题](../mistakes/prototype-003.md)。

1. 阅读本规则、[总控会话](../session/session.md)、对应需求会话，检索[错题索引](../mistakes/README.md)。
2. 确认本次范围、已有成果和剩余工作，避免重复初始化。
3. 涉及桌宠工作时使用[业务边界](desktop-pet-rules.md)；术语就近链接到[术语表](../docs/beagle_glossary.md)。
4. 执行后检查文件、引用和真实结果；有代码再运行与变更匹配的检查，不能以文档完备代替程序运行验收。
5. 更新需求会话和总控会话的状态、变更、验证、继承说明及提交总账。文档交付、本地 Git 提交、远程推送分别记录，禁止编造提交哈希。

## 错误与规则维护

- 错误记录使用[模板](../mistakes/template.md)，写明事实、影响、根因、修复与验证；同类错误归纳到索引的防呆清单。
- 用户新增或调整规则时同步本文件、总控会话及需求会话。
- 通用规则更新优先维护本项目 spec，再同步本地规则和会话；外部原始规范不自动回写。
- 规则自创建起生效，用户当前指令优先。原规范里的 Beagle 游戏术语只是源项目示例，当前仅保留兼容术语表文件名。
